Documentation

Install it, point it at a photograph

boot-effect is one UMD file. It creates a canvas inside the element you give it, analyses the photograph, and plays a 250-frame sequence at 30 fps.

Install

Load the script, or install the package. The library has no dependencies.

Script tag
<script src="https://cdn.jsdelivr.net/gh/adityabhatnagar1/boot-effect@v1.0.0/dist/boot-effect.js"></script>
npm
npm install boot-effect
ES module or CommonJS
import BootEffect from "boot-effect";
// const BootEffect = require("boot-effect");

You can also copy dist/boot-effect.js from the repository and serve it yourself.

Quick start

JavaScript
const fx = new BootEffect("#intro", {
  photo: "sunset.jpg",
  sky: { mode: "warm", horizon: 0.49 },
  onComplete: () => document.body.classList.add("ready")
});

The first argument is an element or a selector. The effect fills it: with layout.height left at "auto" the box takes a 16:9 shape in landscape windows and 9:16 in portrait ones. Give the element its own size, or pass an explicit layout, to override that.

Playback starts as soon as the photograph has loaded and been analysed. Pass autoplay: false to hold on the first frame and call fx.play() yourself.

Photographs

photo accepts a URL string, an HTMLImageElement, an ImageBitmap or a canvas. To use different art for portrait and landscape boxes pass an object:

JavaScript
photo: {
  landscape: "wide.jpg",
  portrait: "tall.jpg"
}

A single image is used for both. The effect picks the variant from the shape of the box and switches if the box changes shape.

  • Resolution. The photograph is the only source of detail. Give it at least the pixel width of the largest screen you care about; the library downscales with a proper filter but cannot invent pixels. The demo photograph is 2576 by 1449.
  • Cross-origin images. A photograph from another origin must be served with CORS headers, because its pixels are read for the analysis.
  • Very large images. If the photograph is larger than the GPU's maximum texture size it is downscaled once on load.
  • Colour. The photograph is sampled as sRGB.

Sky detection

The grid grows out of the sky, so the library needs to know where the sky is. sky: "auto" chooses one of three rules per photograph. Set it explicitly when the guess is wrong.

ModeUse it forHow it decides
blueClear daytime skyBlue-dominant pixels above a brightness floor.
hazeFog, overcast, milky skiesPixels that are bright and locally smooth.
warmSunrise, sunset, duskOrange, pink and violet pixels plus pale glow, kept only where connected to the top edge.

Pass an object to tune a mode:

JavaScript
sky: {
  mode: "warm",
  horizon: 0.49,    // nothing below 49% of the photo height is sky
  connected: true   // keep only sky reachable from the top edge (default for "warm")
}

horizon works in every mode and is the fix for water: a reflection of the sky is bright and colourful too, and without a horizon it would be gridded as well. In haze mode, lo, hi, sdLo and sdHi set the luminance and smoothness ranges.

Call fx.analysis() after onReady to see what was found: the rule that was applied, the centre and radius of the largest clear circle, and the mask itself. The playground shows these live for your own photographs. To override the centre of the effect, pass center: [u, v] in photo coordinates from 0 to 1.

Layout

By default the effect is "inline": a block as wide as its parent, with the height following aspect.

A full-screen intro that removes itself
const intro = new BootEffect(document.body, {
  photo: "hero.jpg",
  layout: "fullscreen",
  hideOnComplete: true
});
intro.done.then((fx) => fx.destroy());

"fullscreen" is a fixed box of 100vw by 100dvh at z-index: 9999. The element ignores pointer events, so it never blocks the page underneath.

Anchored over part of a page
new BootEffect("#card", {
  photo: "hero.jpg",
  layout: { position: "absolute", anchor: "bottom-right", width: "40%" },
  fit: "contain"
});

fit decides how the photograph meets the box: cover fills and crops, contain shows the whole picture and extends the mean sky colour around it, fill stretches. With cover, focus chooses which point of the photograph stays centred, as { portrait: [u, v], landscape: [u, v] }; by default it follows the sky.

Callbacks

CallbackFires
onReady(fx)The photograph is loaded and analysed, before playback starts.
onFrame(frame)After every rendered frame.
onComplete(fx)Playback reached the last frame, or skip() was called.
onSkip()The animation was skipped for reduced motion.
onError(error)The photograph could not be loaded, or WebGL is unavailable.

Accessibility

The element has role="img" and carries label as its accessible name; give it a sentence that says what the visitor is waiting for. With respectReducedMotion on, a visitor whose system asks for reduced motion sees no animation at all: onSkip fires, the instance finishes at once, and you can continue to your page.

The last seconds of the sequence contain fast flashes: a black and white cut, a photograph frame, and flickering speckle. If your audience may include people sensitive to flashing, keep respectReducedMotion on, and consider not using the effect where it cannot be skipped.

Performance

  • One pass per frame. Every phase is the same fragment shader with different uniforms; a frame costs one full-screen draw.
  • Pixel budget. The canvas is sized to the box times the device pixel ratio, capped by maxPixelRatio and maxPixels. If the average frame takes more than 30 ms over 24 frames, the pixel ratio is lowered in steps, down to 55% of what it would otherwise be.
  • Photograph pyramid. Smaller copies of the photograph, each a box-filtered half of the one before, are created on demand so a phone does not downsample a 2500-pixel image with a single bilinear tap.
  • Sampling. The photograph is read with a Catmull-Rom bicubic filter, with optional adaptive sharpening when it is magnified, and the output is dithered by one level to avoid banding in smooth gradients such as skies.
  • Background tabs. Playback pauses while the tab is hidden and resumes when it returns.

When things fail

If the photograph cannot be loaded, or WebGL is unavailable, onError fires. With the default fallback: "photo" the element then shows the still photograph and finishes, so done still resolves and your page can carry on. A lost GPU context is restored automatically and the current frame is redrawn.

TypeScript and React

Typings ship with the package (dist/boot-effect.d.ts). A React wrapper that keeps the layout and playback options live is in the repository at examples/react/BootEffect.tsx:

React
<BootEffect
  photo="/sunset.jpg"
  sky={{ mode: "warm", horizon: 0.49 }}
  layout="fullscreen"
  hideOnComplete
  onComplete={(fx) => fx.destroy()}
/>

Browser support

The library needs WebGL 1, canvas 2D and Promise. ResizeObserver and Image.decode() are used when present. It was developed and rendered in Chromium; it uses only WebGL 1 features, but if you target a specific browser version, check it there.

Spotted something wrong? Open an issue with the browser, the photograph (or a similar one), and the options you used.
